# 新手部署指南：自己的 Drop 临时取件站

只需要 GitHub 账号和 EdgeOne Makers 账号。无需服务器，无需在电脑上安装软件或运行命令。

## 1. 复制项目到自己的 GitHub

打开 [Drop 仓库](https://github.com/nmdft/drop)，点击右上角 **Fork**，再点击 **Create fork**。这会在你的账号下保存一份项目，并不是修改原作者的站点。

## 2. 在 Makers 导入

打开 EdgeOne Makers 控制台，选择从 Git 仓库新建项目，授权读取你刚才 Fork 的仓库，选择 `main` 分支。

构建设置按以下内容填写（如果已经自动识别，核对即可）：

| 设置 | 填写内容 |
| --- | --- |
| 安装命令 | `npm ci` |
| 构建命令 | `npm run build` |
| 输出目录 | `dist` |
| Node.js 版本 | 20 或更高的兼容版本 |

## 3. 直接部署，不用填写随机密钥

点击部署，等待构建完成后打开平台提供的 HTTPS 地址。**新站点不需要设置 `SITE_SECRET` 或 `CLEANUP_SECRET`，也不用生成密码或运行命令。**

第一次访问时，服务端自动生成站点密钥，保存在本项目私有 Blob 的 `config/site-secret-v1` 中。以后实例重启、构建和重新部署都会复用它；不要删除这个配置对象，也不要公开存储内容或访问凭据。并发首次访问由存储协调锁保证只初始化一次。

定时任务的调用凭据在构建时自动生成，同时写进本次部署的私有函数和任务配置，不会放进网页，也不需要手动同步。它与长期站点密钥分开，构建时更新不会使上传、下载和撤销凭证失效。

## 4. 部署，检查结果

等部署状态变为成功，打开 Makers 提供的站点地址，测试：发送一段文字 → 输入取件码领取 → 发送一个小文件并下载 → 撤销后无法再领取。

静态页面、云函数和 Blob 由 Makers 托管，无需另建数据库或填写 Blob 账号。实际额度和费用以你自己的平台套餐为准；长期使用可再绑定自己的 HTTPS 域名。

## 每天清理由 Makers 自己执行

项目已在 `edgeone.json` 配置原生定时任务 **daily-cleanup**：北京时间每天 **03:23**，调用 `/api/scheduled-cleanup`。部署时平台会同步任务，不需要启用 GitHub Actions，也不需要填写 GitHub Secret 或 `SITE_URL`。

构建程序自动配对本次部署的任务调用凭据，由清理函数核验；源码中的配置不包含凭据。不要公开下载后的构建配置或任务请求体，限制有权查看项目配置的人员。它不是端到端加密。

到期立即停止取件；真正删除在定时任务运行时进行。例如保留 1 小时的文件，不需要存满三天。任务会分批处理；大量积压、锁异常或运行时间不足时可能没删完，应检查函数执行日志中的完成／失败记录。健康接口正常不代表定时任务已经成功。

首次部署建议在平台检查任务配置和执行记录；如果控制台提供手动触发入口，可以立即验证，否则观察下一次计划执行。取件是否到期不依赖定时任务准时触发。[官方定时任务说明](https://pages.edgeone.ai/document/edgeone-json)

### 已有站点升级

升级时先保留原有环境变量。第一次访问新版会把原 `SITE_SECRET` 保存到私有 Blob，避免旧凭证失效；确认初始化和取件、上传、撤销均正常后，可以删除 Makers 中旧的 `SITE_SECRET`、`CLEANUP_SECRET`。旧变量暂时保留也不影响自动定时任务。GitHub 的旧清理工作流及其 Secret 不再使用。

不要清空 `config/`。迁移到全新项目、删除站点密钥或清空 Blob 后，旧上传、下载和撤销凭证将不能继续使用；需要保留它们时，应通过受保护的管理员渠道迁移原配置，不能将密钥贴入源码、网页或公开备份。

## 可选：开发与故障排查

只想部署网站可跳过此部分。开发者可按 README 安装依赖、运行测试和构建；静态构建与测试不需要生产密钥。本地完整预览需按 Makers CLI 的开发流程关联独立测试项目及 Blob；站点密钥自动初始化，不要连接生产存储做普通开发。先运行一次构建，以生成仅供服务端使用的定时任务凭据。
