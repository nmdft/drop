# 临时取件站 · Pickup Drop

无需注册，通过随机四位数字取件码，在设备之间传一个文件或一段文字。代码存于私有 GitHub 仓库，动态内容只存于 EdgeOne Makers Blob。

## 产品规则

- 每次发送一个文件或一段纯文字，不支持文件合集。
- 文件最大300MB；本工具已预留容量达到900MB时，文件上限降至1MB。剩余容量检查始终生效。
- 文字最多100KB，按UTF-8字节计算，约能存3.3万个汉字。
- MB以1,000,000字节计算；本工具给每条内容预留8KB元数据，并以980MB为安全容量上限。
- 四位码保留前导零；从发送成功开始，默认1小时，可选3小时、1天、3天。
- 同一个码三天内不复用，即使提前撤销，也保留码的墓碑记录至三天期满。
- 有效期内重复领取。取件码到期后不重新发码。
- 内容在发送成功后保留72小时。此后拒绝访问，每天的清理任务再实际删除，通常可能延迟约24小时，调度故障时更长。
- 未完成上传预留2小时，之后由清理任务回收。

## 技术选择

静态HTML/CSS/JS + Makers Node.js Cloud Functions + `@edgeone/pages-blob`，无SQL数据库和KV。所有Blob存储使用强一致读写。

文件用4MB分块经过后端上传，每块精确检查长度，再保存于Blob。这样不依赖可以被绕过的客户端大小检查或不限制大小的预签名直传。300MB最多75块；后端单请求不必接收或缓存完整300MB。领取时也逐块下载；支持文件系统API的浏览器直接写入选定文件，其他浏览器用内存组装Blob后保存，最多会消耗约300MB以上内存。仅提供下载，不在线执行/预览上传文件。

最新SDK将`onlyIfNew`标记为不可依赖。分配取件码、预留容量、计数、提交、上传分块、撤销和清理使用基于独立Blob记录的Bakery互斥协调，不假设普通读改写是原子的。该协议依赖平台强一致列举和读取；内存模拟并发测试不能替代实际平台验证。协调记录在`finally`释放。实例被强制终止可能留下锁：系统会拒绝新写入，绝不自动抢锁造成双写。运行恢复见下文。

## 防滥用及边界

- 发送前进行17位SHA-256计算验证，签名挑战绑定IP，10分钟有效、只能使用一次。这是轻量成本门槛，**不是人机识别或完整抗DDoS方案**。
- 同IP每小时最多10次发送尝试；每分钟最多12次取件尝试，计数存于Blob。
- 不提供内容公开列表，取件前不泄露文件名或文字。
- 下载令牌签名、绑定具体内容与取件码有效期；每个分块请求再次校验时间及撤销状态。
- 接口不缓存；静态页面设置CSP，文字以`textContent`展示，文件下载为二进制。
- 独立撤销链接可以提前删除，仅供发送者保管。它和取件码链接都放在URL片段中，避免进入普通服务器请求日志。
- 四位码只有10,000种可能，**不提供保密性**。不得上传证件、密码或敏感材料。分布式猜码、机器人、流量攻击仍然可能，正式公开前应在EdgeOne控制台配置限流/WAF/请求额度告警。
- 1GB是免费账户共享额度。本工具的统计只覆盖自己的Blob命名空间，不包括账户其他项目；请用独立空闲额度，或相应降低`lib/service.js`的安全上限。
- 基于Blob全量列举的协调和容量统计适用于小型低流量站点，不是大规模网盘后端。
- 不会撤回已经下载的文件；有效期截止只停止新的服务端访问。

## 本地验证

需要Node.js 20+和EdgeOne CLI：

```sh
npm ci
npm test
npm run build
```

测试使用内存Blob模拟器，不会触碰线上文件，覆盖过期、三天保留、UTF-8大小、文件分块、限流、验证码重复、并发容量和并发取件码等。完整开发预览需要EdgeOne授权及项目关联：

```sh
edgeone login --site china
cp .env.example .env
# 将下列两个密钥填写到.env；不要提交.env
node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
edgeone makers dev -n pickup-drop --skip-env-sync --skip-ai-gateway-sync
```

CLI会使用/关联名为`pickup-drop`的项目；仅在你希望创建该项目时执行。开发入口通常是`http://127.0.0.1:8088/`。修改共享`lib/`代码后，重启Makers开发服务以重新打包函数。

真实HTTP与Blob验收（会产生自己的测试内容，结束后撤销）：

```sh
TEST_URL=http://127.0.0.1:8088 FILE_MB=300 node scripts/smoke.mjs
```

`TEST_URL`也可填写完整的Makers限时预览URL（必须保留校验参数）。脚本先交换授权Cookie，再请求API；限时预览不能用作每日清理的长期地址。`VERIFY_CLEANUP=1`额外验证自己的文字记录到期后不可领取，并确认清理接口物理删除；需要通过环境变量提供`EDGEONE_PROJECT_ID`、`EDGEONE_PAGES_API_TOKEN`和`CLEANUP_SECRET`，不要把凭据写入命令记录或仓库。

空站点的真实并发与容量预留验收：提供上述项目凭据及`SITE_SECRET`，运行`node scripts/storage-check.mjs`。该脚本使用独立Blob客户端并发发送文字，再并发预留三个300MB上传，检查900MB以上只允许1MB，并撤销自己创建的全部记录。它验证的是**实际Blob上的容量预留**，不会为了容量测试再写入900MB文件，也不会删除已有内容；发现站点已有保留内容就拒绝运行。

## 正式部署（Git关联）

1. 在Makers控制台新建项目，关联私有GitHub仓库，选择`main`。
2. 构建命令`npm run build`，输出目录`dist`，安装命令`npm ci`，Node.js 20。Cloud Functions在项目根目录的`cloud-functions/`，不是`dist/`。
3. 添加环境变量`SITE_SECRET`与`CLEANUP_SECRET`，每个至少32字符，分别用密码学随机数生成。两个值不同；不要放在前端、README或Git中。Blob运行凭据由平台注入，不需要写入客户端。
4. 修改环境变量后重新部署，验证`/api/health`返回`{"ok":true,"storage":"reachable"}`，再实测文字、文件和下载。健康接口不是完整验证的替代品。
5. GitHub仓库Secret设置`CLEANUP_SECRET`，与Makers环境变量一致；仓库Variable设置`SITE_URL`为可访问的站点HTTPS根URL。
6. GitHub Actions每天UTC 19:23执行清理（北京时间次日03:23），支持手动运行，逐批删除，直到返回`more:false`。未设置`SITE_URL`时跳过，**不代表清理已运行**。定时任务可能延迟；失败应查看Actions并手动重试。
7. 域名由站点所有者在Makers控制台绑定，并按区域要求处理备案/访问配置；更新`SITE_URL`后手动验证清理。

GitHub只保存代码、配置模板及测试，不保存上传内容、密钥或本地CLI缓存。不要把已有Git关联项目切换成CLI直传项目。

## 异常协调锁恢复

如果所有写入持续显示繁忙、但读取正常，先检查函数日志。实例被强制终止后，协调票据不会自动删除，防止仍在运行的实例和新实例同时进入临界区。

**必须先在平台暂停外部请求/站点流量，并等待至少3分钟，确保超过120秒的函数运行上限，然后才恢复锁；不能在活跃站点上抢锁。**设置自己的项目ID/API Token（不要写入Git），执行：

```sh
EDGEONE_PROJECT_ID=your-project-id EDGEONE_PAGES_API_TOKEN=your-token node scripts/locks.mjs
EDGEONE_PROJECT_ID=your-project-id EDGEONE_PAGES_API_TOKEN=your-token node scripts/locks.mjs --reset-after-pausing-site
```

确认恢复结束后恢复流量，并手动运行清理工作流。工具不会打印Token。
